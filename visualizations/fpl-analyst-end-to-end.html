Shared normalization

Metric scorez = clip((x − league mean) / population SD, −2.5, +2.5)
0–100 mappingscore = clip(50 + 20z, 0, 100); lower-is-better metrics use 100 − score
Meaning50 = comparison-group average; 70/30 ≈ ±1 SD; not a probability and not projected FPL points

Player season aggregates

Per 90metric_per90 = Σ metric / max(total_minutes, 1) × 90
Valuepoints_per_million = total_points / max(latest_cost, 0.1)
Formmean(total_points) across the latest min(5, latest_GW) gameweeks
Last GWΣ total_points where gameweek = latest_GW
Splitshome/away totals for points, goals and xG using parsed was_home

Role-v1 player model

Windowsseason = every available GW; last_5 = latest five available GWs
Eligibilitytotal_minutes ≥ min(450, max(90, 60 × window_gameweeks))
Goal threat40% xG/90 + 25% box shots/90 + 20% shots on target/90 + 15% opponent-box touches/90
Creation50% xA/90 + 30% chances created/90 + 20% assists/90
Forward attack70% goal threat + 30% creation
Midfielder attack50% goal threat + 50% creation
Defender attack45% goal threat + 55% creation
DC eligibility60+ minute appearances only; DEF threshold 10 actions; MID/FWD threshold 12; each hit = 2 points
Defensive floor60% DC hit rate + 25% defensive contributions/90 + 15% minute security
MID hybrid2 × attack × floor / (attack + floor)
DEF complete40% attack + 35% defensive floor + 25% team defense strength
GK score50% team defense strength + 25% normalized clean-sheet rate + 25% normalized points/90

Team-strength model

Team-match attacksum xG, goals, shots, chances from players with minutes > 0
Team-match defensexGC/GC from highest-minute player if ≥80 minutes; otherwise opponent attack aggregates
Season attack40% xG/match + 30% goals/match + 15% shots/match + 15% chances/match
Season defense55% inverse xGC/match + 35% inverse goals conceded/match + 10% clean-sheet rate
Overall50% attack strength + 50% defense strength
Opponent multiplier0.85 + 0.30 × opponent_strength/100
Recent formlatest min(5, latest_GW) team matches, opponent-adjusted before normalization
Fixture recent weightGW≤5: 0%; GW6–9: 25%; GW≥10: 35%
Venue rate60% xG/match + 40% goals/match, home versus away
Venue modifierclip((home_rate − away_rate)/(home_rate + away_rate + 0.1) × 50, −50, 50) × reliability
Venue reliabilityclip((min(home_matches, away_matches) − 2)/4, 0, 1); zero until both splits have 3 matches

Stored fixture model

Current strengthseason_strength × (1 − recent_weight) + recent_score × recent_weight
Venue applicationattack += 15% of venue modifier; defense += 7.5% of venue modifier
Attack differenceown attack − opponent defense
Defense differenceown defense − opponent attack
FDRclip(3 − strength_difference/50, 1, 5); 1 easiest, 5 hardest
Favorabilitystrength_difference / 10; positive is favorable

Legacy quick-pick heuristic still used in club pick modals

Attack score2 × goals/game + 1.5 × assists/game + 0.4 × points/game + 0.2 × form
Defense score4 × clean-sheet rate + 0.05 × cumulative defensive contributions + 0.35 × points/game + 0.2 × form
Top pickattack ≥2.2 OR defense ≥3.0 OR (points/game ≥6 AND form ≥5)
Differential(attack ≥1.6 OR defense ≥2.3) AND ownership <15%
Solid / Monitorsolid: attack ≥1.5 or defense ≥2.0; monitor: attack ≥1.0 or defense ≥1.5; else risky
Important distinction
This unbounded legacy score is not Elo, not a probability, and not the role-v1 0–100 score used by Top Players.

Known boundaries

Main ETL double-gameweek limitation
The production schema key is player + gameweek, and the main validator rejects conflicting player/GW duplicates. Fixture-level player output cannot represent two matches in one GW. The isolated Elo lab uses opponent + venue in its key and can detect legitimate doubles.
Two player scoring generations coexist
Top Players uses role-v1 0–100 scoring; Player Picks still uses the older unbounded attacker/defender heuristic.
Feature flag controls compute location
NEXT_PUBLIC_PLAYER_ROLE_INSIGHTS_PRECOMPUTED=true reads stored role scores. Otherwise every client derives them from paginated gameweek rows.
Latest-season views versus configured season
SQL views choose max(season_key); direct frontend table reads use the configured season. Keep season values aligned during rollover.
